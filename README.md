# Лабораторна робота №1: Реалізація перетворень між системами координат

## 1\. Короткий опис роботи

**Мета:** Спроектувати та реалізувати імутабельні програмні моделі для представлення точок у 2D та 3D системах координат, реалізувати механізми конвертації через статичні фабричні методи та провести порівняльний аналіз продуктивності різних підходів до обчислення відстаней.

**Реалізовані класи:**

  * **CartesianPoint2D / CartesianPoint3D**: Моделі для декартової системи координат.
  * **PolarPoint**: Модель для полярної системи (радіус та кут у радіанах).
  * **SphericalPoint**: Модель для сферичної системи (радіус, азимут та полярний кут у радіанах).

Всі класи реалізовані як **імутабельні** (frozen dataclasses), що забезпечує цілісність даних після їх створення та відповідає сучасним стандартам безпечного програмування.

## 3\. Результати перевірки коректності

Для підтвердження правильності алгоритмів було проведено тестування шляхом послідовної конвертації (Round-trip conversion). Програма перетворює декартові координати в полярні/сферичні, а потім повертає їх у декартовий вигляд, порівнюючи кінцеві значення з вихідними.

## 4. Результати аналізу продуктивності (Бенчмаркінг)

Тестування проводилось на вибірці з **100,000 пар точок**. Вимірювався чистий час виконання математичних операцій без врахування часу на створення об'єктів.

| Метод обчислення | Час виконання (секунди) |
| :--- | :--- |
| 2D Polar (Law of Cosines) | 0.08067 |
| 2D Cartesian (Euclidean) | 0.05896 |
| 3D Spherical Chord | 0.14959 |
| 3D Spherical Arc (Great Circle) | 0.13369 |
| 3D Cartesian (Euclidean) | 0.07941 |

### Аналіз та висновки

* **Для 2D:** Декартова система координат показала кращу продуктивність (приблизно на 27% швидше за полярну). Це підтверджує, що прості арифметичні операції Евклідової відстані обробляються швидше, ніж тригонометричні розрахунки за теоремою косинусів, які потребують більше циклів CPU.
* **Для 3D:** Найшвидшим методом залишається декартова система (0.07941 с). Найбільші часові витрати у даному тесті продемонстрував метод сферичної хорди (0.14959 с), що пов'язано зі складністю математичних операцій для кожної пари точок. Сферична дуга (Arc) виявилася дещо швидшою за хорду, проте обидва сферичні методи значно поступаються декартовому у швидкодії.

## 5. Загальні висновки

В ході виконання лабораторної роботи було реалізовано систему перетворення координат з дотриманням принципу імутабельності даних. Проведений бенчмаркінг наочно продемонстрував перевагу декартової системи координат у контексті швидкості обчислень. Отримані результати підтверджують, що для оптимізації програмного забезпечення, яке працює з великими масивами геометрії, доцільно використовувати декартові представлення для масових розрахунків відстаней, залишаючи полярні та сферичні моделі лише для специфічних задач введення даних або візуалізації.
